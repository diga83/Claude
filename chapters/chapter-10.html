📋 Paper 2 Strategy — How to Maximise Marks

1. Read the scenario carefully first: Understand the context before starting any task. Who is the client? What is the purpose?

2. Work through tasks in order: Tasks build on each other; later tasks may reference earlier output.

3. Check the mark allocation: Higher mark tasks need more detail. A 6-mark web page needs more than a 2-mark formatted paragraph.

4. Proofread against source data: Transcription errors (wrong names, wrong numbers) lose marks that cannot be recovered.

5. Check house style requirements: Font, colour, logo — must match specified style throughout all documents.

6. Save frequently: Ctrl+S every few minutes. System failures do occur and extra time is not normally given.

7. Print before time is called: Allow 15+ minutes for printing. Printed evidence is required for most tasks.

8. Label printed output: Candidate number on every printed page.

📌 Font Choice — Serif vs Sans-Serif

Serif fonts (Times New Roman, Georgia, Garamond): Have small decorative strokes ('serifs') at the ends of letters. Traditional; formal; perceived as more readable in long printed text.

Sans-serif fonts (Arial, Calibri, Helvetica): Clean lines with no decorative strokes. Modern; clean; more readable on screen; often used for headings and digital content.

Spec 5.3.2: 'Use styles appropriately, including serif and sans-serif fonts, colour choice.' You may be asked to justify a font choice or apply a specified house style.

Exam answer: 'Arial is a sans-serif font which is more readable on screen and gives the newsletter a modern, clean appearance appropriate for a youth audience.'

📋 Mail Merge — Key Points

Data source formats: Can be a spreadsheet (.xlsx/.csv), database (.accdb) or another word-processed document with a table.

Merge field syntax: Fields appear in the template as <> or {MERGEFIELD FirstName} — replaced by actual data when merged.

Common uses: Personalised letters (Dear <>); personalised certificates; addressed envelopes/labels; event invitations.

Important: The merge field name in the template MUST exactly match the column header in the data source (case-sensitive in some applications).

Output options: Merge to new document (shows all merged copies); merge to printer (prints directly); merge to email (sends individually).

⚡ EXAM TIP

Mail merge exam question: 'Describe the process of creating a personalised letter for 50 customers using mail merge.' Steps: (1) Create spreadsheet with customer data (Name, Address etc.) as columns. (2) Create letter template in word processor with Dear <> and <

> merge fields. (3) Connect the template to the data source. (4) Preview one merged letter to check it looks correct. (5) Complete the merge to create 50 individual letters. (6) Print all 50.

3.3 Validation Rules

Validation checks are automatic rules applied to fields to ensure only appropriate data is entered. They do not guarantee accuracy — they only check that data is in the right format.

Validation CheckWhat It DoesExample RuleError Scenario Caught
Presence CheckEnsures a required field is not left emptyName field cannot be blank — user must enter a valueCustomer submitted form without entering email address
Range CheckEnsures a numeric value falls within acceptable minimum and maximum limitsAge must be between 5 and 120; Temperature between -50 and 60User enters age as 200 or -5 — both outside real-world range
Type CheckEnsures the data entered matches the expected data type for that fieldPhone number field: must contain only digitsUser types 'N/A' in a number-only field
Length CheckEnsures text is not too short or too long for the fieldPostcode: minimum 5, maximum 8 charactersUser enters a 2-character postcode (too short) or 20 characters (too long)
Format CheckEnsures data matches a required pattern or formatDate: DD/MM/YYYY; Email: must contain @ and domainUser types '25-12-2024' when DD/MM/YYYY format required
Lookup / List CheckEnsures value matches one from a predefined list of acceptable valuesStatus must be one of: Active, Inactive, PendingUser types 'Actve' (misspelling) — not in the permitted list
💡 Validation vs Verification — Critical Distinction

Validation: Automated check by the computer that data meets defined rules (type, range, length, presence, format). The computer rejects invalid data.

Verification: Human double-checking that data entered matches the original source — the computer cannot do this. Proofreading, double data entry.

Example: A range check validates that age is 0–120. But if someone misreads '26' as '62', both pass the range check — only verification (comparing to original) catches it.

Exam question: 'Validation cannot guarantee data is accurate — explain why.' Answer: Validation only checks that data is in an acceptable format; it cannot verify that the data is correct. For example, the date 01/01/1990 passes all date validation even if the actual date should be 01/01/2000.

📋 Writing a Database Query — Example

Scenario: Find all students in Year 11 who scored over 75 in Maths.

Criteria: Year = 11 AND MathsScore > 75

In query design view: Field: Year, Criteria: 11; Field: MathsScore, Criteria: >75 (on the same row = AND)

Result: Shows only records where BOTH conditions are true — multiple criteria on same row = AND; different rows = OR.

Sort: Can additionally sort by LastName Ascending to produce an alphabetical list.

Output: Report, query result table, mail merge document, form view — all are valid output formats from spec 6.2.7.

🔍 VLOOKUP Explained — Step by Step

Syntax: =VLOOKUP(lookup_value, table_array, col_index_num, [range_lookup])

lookup_value: The value to search for — e.g. a product code in cell A2

table_array: The range containing the lookup table — e.g. Products!A:D (must start with the column being searched)

col_index_num: Which column of the table to return — 1=first column, 2=second column, etc.

range_lookup: FALSE = exact match (almost always use FALSE); TRUE = approximate match (sorted data only)

Example: =VLOOKUP(A2, Products!$A:$D, 3, FALSE) — finds the value in A2 in column A of Products sheet; returns value from column 3 of that sheet

Common error: If lookup value not found: returns #N/A error — use IFERROR to handle: =IFERROR(VLOOKUP(...),'Not found')

📌 Absolute vs Relative References — The Key Distinction

Relative reference (A1): When you copy the formula, the reference adjusts automatically. =A2+B2 copied down becomes =A3+B3.

Absolute reference ($A$1): Reference stays FIXED when copied. =$A$1+B2 copied down stays =$A$1+B3 (A1 is locked).

Mixed references: $A1 = column locked, row adjusts. A$1 = row locked, column adjusts.

When to use absolute: When formula references a fixed value used in many calculations — e.g. a VAT rate in one cell used across all price calculations.

Example: =B2*$C$1 — multiplies B2 by the VAT rate in C1. When copied down, B2 becomes B3, B4 etc. but C1 stays fixed.

📌 Action Buttons vs Hyperlinks vs Animations — Know the Difference

Hyperlink: Links text or object to another slide, file or URL — navigates when clicked during slideshow.

Action button: Pre-designed clickable button (Next, Previous, Home, Custom) — appears as a shape with built-in navigation action.

Animation: Applies an effect to a single object ON THE SLIDE (it appears, moves, or disappears during the presentation).

Transition: Applies an effect BETWEEN slides — the visual effect as one slide disappears and the next appears.

Exam trap: 'Add an animation to make the title appear' = Animation (on the slide element). 'Add a transition between slide 1 and slide 2' = Transition (between slides). Never confuse these.

📐 Shapes in the Spec — Know These

Rectangles (including squares): Insert > Shapes > Rectangle. Hold Shift while drawing to create a perfect square. Can be filled with colour, given borders, contain text.

9. Common Mistakes in Paper 2

✗ COMMON MISTAKES IN THE PRACTICAL EXAM

✗ Using wrong data type — storing prices as Text/Alphanumeric instead of Currency means you cannot use them in calculations. Always check data type against what the data will be used for.

✗ Forgetting to add both header AND footer to printed documents — many tasks require a specific header (e.g. candidate name) AND footer (page number). Both must appear on the printed evidence.

✗ Leaving merge fields visible — if mail merge fields appear as <> in the output, the merge was not completed. Always finish the merge and check the personalised output.

✗ Using relative references where absolute are needed — =B2C1 copied down gives =B3C2, =B4C3 etc. If C1 is a fixed tax rate, use =B2$C$1 instead.

✗ Selecting wrong chart type — using a pie chart for data that changes over time (use line chart) or using a line chart for categories with no time element (use bar chart).

✗ Not labelling axes on charts — axis labels (including units) are required for full marks. 'Revenue' and 'Month' are labels; 'Revenue (£)' and 'Month (Jan–Dec)' are complete labels.

✗ Confusing AND/OR in queries — AND shows only records matching ALL criteria (smaller result set). OR shows records matching ANY criterion (larger result set). Wrong operator gives completely wrong query output.

✗ Not merging cells in table headers — if a header spans multiple columns, it should be merged. Unmerged headers look like separate cells with repeated text — examiner will penalise this.

✗ Saving web images in wrong format — photographs should be JPG; images with transparency should be PNG; saving as BMP creates huge files incompatible with web browsers.

✗ Forgetting alt text on images in web pages — screen readers use alt text; missing alt text is poor accessibility practice and may lose marks in web authoring tasks.

✗ Not applying a master slide change to all slides — if told to add a logo to all slides, add it to the MASTER SLIDE not to each slide individually. Master slide change = automatic on all slides.

✗ Using Comic Sans, WordArt, or excessive decorative fonts — professional documents require professional typography. Unless specified, use clean readable fonts throughout.

📐 Absolute vs Relative References — Last-Minute Reminder

Relative A1: Adjusts when copied — =A2+B2 copied down becomes =A3+B3

Absolute $A$1: Stays fixed when copied — =$A$1*B2 copied down keeps $A$1

Mixed $A1: Column locked, row adjusts. A$1: Row locked, column adjusts

Rule: Use $ to lock any cell reference that should NOT change when the formula is replicated

📊 Chart Types — Quick Selection Guide

Pie chart: Parts of a whole at ONE point in time — proportions adding to 100%

Bar / Column chart: Comparing quantities across CATEGORIES (discrete data)

Line chart: Trends OVER TIME (continuous data across periods)

Scatter graph: Correlation between TWO VARIABLES — shows relationship pattern

All charts must have: Title + Axis labels with units + Legend (if multiple series)
