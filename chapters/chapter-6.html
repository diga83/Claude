1. Peer-to-Peer vs Client-Server Networks [Spec 2.4.1]

📋 SPEC 2.4.1

Know about peer-to-peer and client-server networks.

The two fundamental network architectures differ in how control and resources are distributed. Understanding both their structures and their advantages and disadvantages is essential.

PEER-TO-PEER (P2P) All devices are EQUAL — each can act as both client and serverCLIENT-SERVER Dedicated SERVER provides services; CLIENTS request them
PC1 ↔ PC2 ↔ PC3 (all equal nodes)SERVER ← requests — CLIENTS (PC1, PC2, PC3…)
No central control — each device manages its own dataServer controls storage, software, authentication, backups
Easy to set up — no server hardware requiredRequires powerful server hardware and IT management
Files stored on individual devices — not centralisedAll files stored centrally on server — accessible from any device
If one PC fails, only that user is affectedIf server fails, ALL clients lose access simultaneously
Security harder to enforce — no central controlIT admin enforces security policies across all devices centrally
✓ Cheap; simple; good for home/small groups✓ Secure; centralised; scales to large organisations
✗ No central admin; poor security; files at risk✗ Expensive server; needs skilled IT staff; single point of failure
Example: Home file sharing between 2 PCs; BitTorrentExample: School network; corporate office; hospital system
📌 When to Choose Which — Exam Scenarios

Choose P2P when: Small number of users (2–10); low budget; simple file sharing; no dedicated IT staff; home environment.

Choose client-server when: Large organisation (10+ users); centralised control needed; security is important; automatic backup required; professional environment (school, hospital, corporation).

Exam tip: If a question describes a school, hospital or business with many users, always recommend CLIENT-SERVER. Justify with at least TWO specific benefits from spec 2.4.4.

⚡ EXAM TIP

'Describe ONE advantage and ONE disadvantage of a peer-to-peer network.' Advantage: Peer-to-peer networks are cheap to set up (1) because no dedicated server hardware is required — each device connects directly to the others (1). Disadvantage: Security is difficult to manage on a peer-to-peer network (1) because there is no central administrator to enforce password policies or control access to shared files (1).

2. Role of Servers in a Client-Server Network [Spec 2.4.2]

📋 SPEC 2.4.2

Know about the role of servers in a client-server network.

Different types of server perform different specialised functions. Most real networks have multiple servers — each dedicated to one role for maximum efficiency and security.

File Server Stores and manages all files and documents for users on the network Benefit: Centralised storage; accessible from any device; no need to carry files e.g. School file server storing all student work in organised foldersPrint Server Manages print jobs from multiple users and queues them to shared printers Benefit: Multiple users share printers; print spooling prevents conflicts; print usage tracked e.g. Office print server queuing 20 staff print jobs to 2 shared printersWeb Server Hosts websites and serves web pages to browsers that request them via HTTP/HTTPS Benefit: Single server serves all website visitors; easily updated; accessible globally e.g. School website server; e-commerce website; online learning platform
Email Server Sends, receives and stores email messages for all users on the domain Benefit: Centralised email management; filtering; archiving; accessible from any device e.g. Company email server managing all staff@company.com addressesAuthentication Server Verifies user identities — checks usernames and passwords against a central database Benefit: Single login for all network resources; centralised account management; audit trail e.g. School login server checking student credentials before granting accessDatabase Server Stores and manages large structured databases; responds to queries from client applications Benefit: Shared access to consistent data; query optimisation; access control per table/field e.g. Hospital patient database server; bank transaction server
Backup Server Automatically copies data from all devices/servers to secure backup storage Benefit: Data recovery possible after failure; scheduled automatic backups; version history e.g. Backup server running nightly full backup of all school files at 2am

⚡ EXAM TIP

'Describe TWO benefits of connecting computers in a school using a local area network.' Answer: (1) Shared peripherals — all 30 computers can share 2 network printers (1), which means the school saves money compared to buying a printer for each computer (1). (2) Shared data — students can save work on one computer and access it from any other computer on the network (1), which is useful when students move between different classrooms for different lessons (1).

4. Benefits of Client-Server Networks [Spec 2.4.4]

📋 SPEC 2.4.4

Benefits of client-server: control of user access rights, centralised administration, centralised backup, shared software, shared storage and file access, roaming profiles.

These are SPECIFIC benefits of the client-server architecture — different from general LAN benefits. The spec requires you to know all six. Each is made possible by the central server.

Client-Server BenefitWhat It Means in PracticeExample
Control of User Access RightsIT admin sets exactly what each user can access — read-only, read-write, or no access per folder/fileStudents can read shared resources but cannot delete or modify them; teachers can edit
Centralised AdministrationAll user accounts, software, security policies and updates managed from one serverIT technician pushes antivirus update to all 300 computers overnight from the server
Centralised BackupServer automatically backs up all data — users don't need to remember to back upSchool server backs up all student work at 3am every night; data recoverable if drive fails
Shared SoftwareSoftware installed on the server once and delivered to all client computers on demandOffice 365 licensed on server; available on every school computer without individual installs
Shared Storage and File AccessFiles stored on server are accessible from any client; no need to copy files to each PCMarketing team all edit the same presentation stored on the server simultaneously
Roaming Profiles (Hotdesking)User's settings, desktop and files follow them to any computer they log intoSupply teacher logs into any available PC; sees their own desktop and files instantly
💡 Client-Server vs LAN Benefits — Don't Mix Them Up

LAN benefits (2.4.3): General advantages of having any network — shared printers, shared internet, flexible access.

Client-server benefits (2.4.4): Advantages specifically from having a DEDICATED SERVER — centralised backup, access rights control, roaming profiles.

Exam trap: 'Shared data' appears in both — but the mechanism is different. In a LAN generally, data is on shared drives. In client-server, data is managed BY the server with access rights control. The client-server version is MORE secure and controlled.

5. Network Security — Threats [Spec 2.5.1 Background]

To understand security methods, you must first understand what they are protecting against. These threats are tested in scenario questions where you must match the right method to the right threat.

5.1 Eight Key Threats

1. Unauthorised Access Someone gains access to a system or data without permission — through stolen passwords, brute force, or exploiting weak security2. Malware (Malicious Software) Software designed to damage, disrupt or gain access to computer systems — includes viruses, ransomware, spyware, Trojans, worms
3. Phishing Fraudulent emails/messages that trick users into revealing passwords, bank details or clicking malicious links — appear to come from legitimate sources4. Pharming Redirects users from legitimate websites to fake ones without their knowledge — by corrupting DNS records or infecting their router
5. Data Interception Capturing data as it travels across a network — especially on unsecured Wi-Fi where packets can be read by nearby attackers6. Denial of Service (DoS) Floods a server with fake requests until it crashes, denying legitimate users access — often used to extort money or damage competitors
7. SQL Injection Attacker inserts malicious SQL code into a web form to manipulate the database — can expose, modify or delete all data8. Social Engineering Manipulating people into revealing confidential information or performing actions — exploits human trust rather than technical vulnerabilities

5.3 Phishing vs Pharming — Critical Comparison

These two attacks are frequently confused. Memorise the key distinction: phishing needs the USER to act; pharming is fully technical and invisible to the user.

FeaturePhishingPharming
What it isFraudulent message (email/text/phone) impersonating a legitimate organisation to trick the userRedirecting users from genuine websites to fake ones silently — without a deceptive message
Attack methodSocial engineering — relies on the USER clicking a link or entering dataTechnical — corrupts DNS records or router settings so the correct URL leads to a fake site
User action requiredYES — user must click link and enter informationNO — user types the correct URL but is silently redirected
How to spot itCheck sender email address; hover over links; look for urgency languageVery hard to spot — URL looks correct; browser shows no obvious warning
PreventionNever click email links; type URLs directly; use multi-factor authenticationKeep router/DNS secure; use HTTPS; check SSL certificate matches domain
ExampleEmail: 'Your PayPal account is suspended — click here to verify' links to fake PayPal siteUser types barclays.com; corrupted DNS redirects to fake banking site that steals login
🔍 How to Spot Phishing — Checklist

✓ Check the SENDER'S email address — phishing emails use slight misspellings (paypa1.com, bank-secure.net)

✓ HOVER over links before clicking — does the URL shown match where it claims to go?

✓ Look for URGENCY language — 'Your account will be closed in 24 hours' is a manipulation tactic

✓ Unexpected attachments — legitimate banks NEVER email you an attachment asking for personal details

✓ Poor grammar and spelling — many phishing emails contain errors that legitimate companies would not make

✓ When in doubt — navigate DIRECTLY to the website by typing the URL; call the company's official number

6. Security Methods [Spec 2.5.1]

📋 SPEC 2.5.1

Know about and understand: log-ins and passwords, firewalls, WEP/WPA, encryption, VPN, file access rights, transaction logs and backups.

The spec lists nine security methods. You must know what each one does, HOW it works, and when to use it. The card grid below covers all nine.

Firewall Monitors all incoming and outgoing network traffic; blocks packets that don't meet security rules How: Can be hardware (physical device) or software (program); uses rules/ACLs to filter by IP, port, protocol Protects against: Unauthorised access; malware communication; DoS attacks e.g. School firewall blocks students accessing social media during lessons; blocks suspicious foreign IPsEncryption Converts readable data (plaintext) into scrambled form (ciphertext) using a mathematical key How: Sender encrypts with a key; only recipient with matching decryption key can read the data Protects against: Data interception during transmission; theft of stored data; eavesdropping on Wi-Fi e.g. HTTPS uses TLS encryption — all data sent to/from bank website is encrypted; credit card number securePasswords & Authentication Requires users to prove identity before granting access to a system or data How: Username + password; PIN; security questions; CAPTCHA; biometrics (fingerprint, face) Protects against: Unauthorised access; account takeover; impersonation e.g. Student must enter school username and password before accessing school files; CAPTCHA prevents bot login
Anti-Malware / Antivirus Detects, quarantines and removes malicious software from devices How: Scans files against database of known malware signatures; heuristic analysis for unknown threats Protects against: Viruses; ransomware; spyware; Trojans; worms e.g. Norton scans downloaded file; detects ransomware signature; quarantines before it can executeWEP / WPA Encryption Encrypts data transmitted over a Wi-Fi network to prevent eavesdropping by nearby devices How: WEP (old, weak — cracked in minutes); WPA2 and WPA3 (current standard — very strong AES encryption) Protects against: Wi-Fi eavesdropping; man-in-the-middle attacks on wireless networks e.g. Home Wi-Fi router uses WPA3 — anyone nearby with a Wi-Fi adapter cannot read your dataAccess Rights / File Permissions Controls exactly what each user can do with specific files, folders or system resources How: IT admin sets permissions per user or group: read-only / read-write / no access / execute Protects against: Accidental or deliberate deletion; unauthorised modification; data leakage between users e.g. Students: read-only on shared resources. Teachers: read-write on their own folders. Admin: full access
VPN (Virtual Private Network) Creates an encrypted tunnel between the user's device and a remote server, masking identity and data How: All traffic routed through VPN server; IP address hidden; data encrypted end-to-end through public internet Protects against: Data interception on public Wi-Fi; identity tracking; geo-blocking; remote worker security e.g. Employee connects to company VPN from café Wi-Fi; all data encrypted; appears to come from company IPTransaction Logs / Audit Trails Automatically records all access attempts, file changes, logins and network activity in a log file How: System timestamps and records every action — who accessed what, when, from which device, success or failure Protects against: Undetected breaches; insider threats; provides forensic evidence after an incident e.g. Bank logs every login attempt; failed logins trigger security alert; forensic trail for fraud investigationBackup Procedures Regularly copying data to a separate location so it can be restored if original is lost, corrupted or encrypted How: Full, incremental or differential backups; stored offsite or in cloud; tested regularly for restoreability Protects against: Ransomware (restore from clean backup); hardware failure; accidental deletion; fire/flood e.g. School runs full backup every night at 2am to off-site cloud storage; student recovers deleted essay from yesterday's backup

6.1 Encryption — How It Works

Encryption is one of the most important security methods. Understanding the mechanism (not just 'it scrambles data') is needed for full marks.

PLAINTEXT Hello, my password is abc123→ENCRYPTION KEY AES-256: k9mX#2pQrL→CIPHERTEXT X8#kLm@9pQ$rT7&wZv
Readable by everyoneApplied during transmissionUnreadable without decryption key
📌 Types of Encryption You Should Know

Symmetric encryption: Same key used to encrypt and decrypt. Fast but key must be shared securely (e.g. AES — used in Wi-Fi WPA2/3).

Asymmetric encryption: Public key encrypts; only matching private key decrypts. Secure key exchange without meeting (e.g. RSA — used in HTTPS/TLS).

HTTPS/TLS: Websites with HTTPS use TLS encryption — all data between browser and server is encrypted. Look for padlock icon.

End-to-end encryption: Data encrypted on sender's device; only decrypted on recipient's device. Even the service provider cannot read it (e.g. WhatsApp messages).

Exam tip: When asked 'how does encryption protect data?', always say: 'Even if data is intercepted during transmission, it cannot be read without the decryption key'.

🔐 Multi-Factor Authentication (MFA) — Why It Matters

MFA combines: Something you KNOW (password) + Something you HAVE (phone/token) + Something you ARE (fingerprint/face)

Why it is powerful: Even if an attacker steals your password through phishing, they still cannot log in without your phone or fingerprint.

Real example: Online banking — you enter your password, then receive a one-time code by SMS that you must also enter within 30 seconds.

Exam tip: If asked to improve security beyond 'use a stronger password', always suggest MFA as a second layer — it's one of the most effective security improvements available.

⚡ EXAM TIP

'Explain why WPA2 is more secure than WEP for a home Wi-Fi network.' Answer: WPA2 uses AES encryption with a 128-bit key (1), which is extremely difficult to crack with current computing power (1). WEP uses the weaker RC4 cipher with only a 40-bit key (1) and has known flaws that allow it to be cracked in a matter of minutes using freely available software (1).

6.4 VPN — How It Works

User Device (Employee laptop) At café with public Wi-Fi→Encrypted VPN Tunnel All data scrambled — cannot be read→VPN Server (Company/Provider) Decrypts and forwards traffic→Destination (Company network / web) Sees traffic from VPN IP, not user IP
Without VPN: public Wi-Fi users can intercept dataWithout VPN: ISP can see all your trafficVPN server hides your real IP addressCompany resources protected; location masked
💡 When to Use a VPN

Public Wi-Fi (café, airport, hotel): VPN encrypts all traffic — prevents other users on the same network from intercepting your data.

Remote working: Employee connects to company VPN to securely access internal company resources as if they were in the office.

Privacy from ISP: ISP cannot see your browsing history when VPN is active.

NOT a complete security solution: VPN does not protect against malware, phishing, or weak passwords — it only encrypts the connection.

6.5 Backup Procedures

Backups are the LAST LINE OF DEFENCE — if all other security measures fail (ransomware encrypts files), backups allow data to be restored from before the attack.

Backup TypeWhat It Backs UpFrequencyStorage RequiredRestore TimeBest Used When
Full BackupALL data — every file regardless of when last changedWeekly or monthlyHighest — complete copy every timeFastest — single backup set to restoreStarting a backup strategy; maximum protection needed
Incremental BackupOnly data changed since the LAST backup (full or incremental)Daily or hourlyMinimal each time — only changesSlowest — must restore full + all incrementals in chainSpace is limited; frequent backups needed
Differential BackupAll data changed since the last FULL backup (not since last backup)DailyGrows each day between full backupsMedium — restore full + latest differential onlyBalance of space efficiency and restore speed
Mirror Backup (RAID)Identical real-time copy on a second drive (or array)Continuous / real-timeDouble the storageInstant — failover is automaticMission-critical systems requiring zero downtime
📋 Backup Best Practice — The 3-2-1 Rule

3: Keep 3 copies of your data (original + 2 backups)

2: Store backups on 2 different types of media (e.g. external HDD + cloud)

1: Keep 1 copy offsite (cloud, different building) — protects against fire, flood, theft

Why offsite matters: Ransomware often encrypts local drives AND connected USB drives. An offsite or cloud backup that is not connected to the system remains safe.

Test restores regularly: A backup that cannot be successfully restored is worthless. Organisations should test recovery monthly.

🎯 Security Selection Answer Framework

Step 1. Identify the threat: What specific risk is described in the scenario (phishing? unauthorised access? data interception?)

Step 2. Name the security method: Be specific ('WPA3 encryption' not just 'encryption'; 'multi-factor authentication' not just 'passwords')

Step 3. Explain HOW it works: Describe the mechanism — not just 'it protects the data'

Step 4. Link to the scenario: Explain WHY this method is suitable for THIS specific situation

Example: 'A VPN (1) should be used because it creates an encrypted tunnel between the employee's laptop and the company server (1). This means that even if the café's Wi-Fi network is monitored by an attacker, all data including login credentials and business files will appear as scrambled ciphertext and cannot be read (1).'

8. Model Answers

Study the structure carefully: security method named → HOW it works → WHY it helps in the specific scenario. Generic answers never score full marks.

✎ MODEL ANSWER

[4 marks]

Q: Describe TWO benefits of using a client-server network instead of a peer-to-peer network for a school with 300 students. [4 marks]

1. Centralised backup (1) — in a client-server network, the server automatically backs up all student files at a scheduled time, meaning if a student's work is accidentally deleted or a computer fails, the IT administrator can restore it from the server backup (1). 2. Control of user access rights (1) — the IT administrator can set specific permissions for each user, so students can only access their own files and shared learning resources, while teachers have access to mark schemes and administrative documents that students cannot read or modify (1).

Why this scores full marks: ✓ TWO distinct client-server benefits — from spec 2.4.4, not generic LAN benefits ✓ Benefit 1: backup explained with consequence (recovery after failure or accident) linked to school context ✓ Benefit 2: access rights explained with specific example (students vs teachers) linked to school context ✓ Each benefit earns 2 marks: the benefit named (1) + the explanation/consequence (1)

✎ MODEL ANSWER

[3 marks]

Q: Explain how encryption protects data transmitted between a user's browser and a bank's website. [3 marks]

When the user sends their login details or bank account information to the website, encryption converts the data from readable plaintext into scrambled ciphertext using a mathematical key (1). If an attacker intercepts the data as it travels across the internet, they will only see the encrypted ciphertext — which is unreadable without the corresponding decryption key (1). The bank's server holds the matching decryption key and can convert the data back to readable form, while the attacker cannot read the data even if they capture it (1).

Why this scores full marks: ✓ Three separate marks: encryption process (1), interception still useless (1), only bank can decrypt (1) ✓ Plaintext and ciphertext terminology used — shows precise understanding ✓ Answer explains the mechanism, not just 'it scrambles the data' ✓ Linked to the bank/browser scenario throughout

✎ MODEL ANSWER

[4 marks]

Q: A company employee wants to work from home and access confidential company files over the internet. Describe how a VPN could be used to do this securely and explain TWO specific benefits. [4 marks]

The employee installs a VPN client on their laptop. When they connect, all internet traffic is routed through an encrypted tunnel to the company's VPN server before reaching the company's internal network. Benefit 1: All data is encrypted in transit (1), which means that even if an attacker intercepts the connection, they cannot read the confidential files because the data appears as scrambled ciphertext (1). Benefit 2: The employee's device appears to be located within the company's internal network (1), allowing them to access files, internal systems and databases that would normally only be available when physically in the office (1).

Why this scores full marks: ✓ How VPN works: tunnel + encryption + routing through company server — described clearly ✓ Benefit 1: encryption explained with consequence (attacker cannot read data) ✓ Benefit 2: appears as internal device — explains WHY remote access works, not just that it does ✓ All parts linked to the scenario (employee, home, confidential files)

9. Common Mistakes

✗ COMMON MISTAKES

✗ Confusing LAN benefits (2.4.3) with client-server benefits (2.4.4) — 'shared data' appears in both, but client-server adds access rights control and centralised management. Know which list each benefit belongs to.

✗ Saying 'encryption stops hackers' — encryption does not STOP interception; it makes intercepted data UNREADABLE. An attacker can still capture encrypted data — they just cannot read it.

✗ Describing WEP as a current security standard — WEP was deprecated decades ago and is trivially cracked. Always recommend WPA2 minimum or WPA3 where available.

✗ Confusing phishing and pharming — phishing uses deceptive MESSAGES to trick users; pharming uses TECHNICAL methods to silently redirect. The key difference: pharming requires no user mistake — even a careful user can be redirected.

✗ Saying 'use a strong password' as the only security measure — for any serious security question, MFA should be mentioned as a second layer. A strong password alone is still vulnerable to phishing.

✗ Describing a firewall as stopping viruses — a firewall controls NETWORK TRAFFIC (blocks unauthorised connections). Antivirus/anti-malware scans and removes malicious SOFTWARE. They protect against different threats.

✗ Writing 'backup protects against hackers' — backup protects against DATA LOSS (from ransomware, hardware failure, accidental deletion). It does not prevent the attack from happening.

✗ Mixing up full, incremental and differential backups — full backs up everything; incremental backs up only changes since last backup; differential backs up changes since last FULL backup. The restore process differs for each.

✗ Listing security methods without linking to the scenario — '(1) firewall' scores 0 in a 'suggest security method' question. Always explain what the firewall does and why it is appropriate for the specific context.

✗ Saying P2P is always worse than client-server — for a home with 2 computers sharing files, P2P is perfectly appropriate and simpler to set up. Only recommend client-server when the scenario clearly describes a larger organisation.

11. Quick Reference — Key Terms & Revision

★ KEY TERMS — QUICK REFERENCE

Peer-to-Peer (P2P) Network: A network where all devices are equal — each acts as both client and server; no dedicated server

Client-Server Network: A network with dedicated server(s) providing services to client devices that request them

Server: A powerful computer providing services (files, print, web, email, auth) to clients on a network

Roaming Profile: User's settings, files and desktop follow them to any computer they log into on the client-server network

Hotdesking: Working at any available workstation rather than having a fixed desk — enabled by roaming profiles

Firewall: Hardware or software that monitors and filters network traffic based on security rules to prevent unauthorised access

Encryption: Converting readable plaintext data into scrambled ciphertext using a mathematical key — only decryptable with the correct key

TLS / HTTPS: Transport Layer Security — the encryption protocol used by secure websites (HTTPS); protects data in transit

WEP: Wired Equivalent Privacy — old, insecure Wi-Fi encryption standard; easily cracked; should not be used

WPA2 / WPA3: Wi-Fi Protected Access — strong Wi-Fi encryption standards; WPA3 is the latest and most secure

VPN (Virtual Private Network): Creates an encrypted tunnel between the user and a server, hiding the user's IP and protecting data on public networks

Access Rights / Permissions: Rules set by an admin defining what each user can do with specific files/folders (read, write, execute, delete)

Authentication: The process of verifying the identity of a user before granting access (password, PIN, biometrics)

CAPTCHA: Completely Automated Public Turing test to tell Computers and Humans Apart — challenge to prevent bot logins

Multi-Factor Authentication (MFA): Requires two or more different types of proof of identity (e.g. password + phone code)

Transaction Log / Audit Trail: A record of all system events — logins, file access, changes — used for security monitoring and forensic investigation

Backup: A copy of data stored separately so it can be restored if the original is lost, corrupted or encrypted by ransomware

Malware: Malicious software designed to damage, disrupt or gain unauthorised access to systems (viruses, ransomware, spyware…)

Phishing: A social engineering attack using fraudulent messages to trick users into revealing credentials or clicking malicious links

Pharming: A technical attack that silently redirects users from legitimate websites to fake ones via DNS manipulation

Ransomware: Malware that encrypts the victim's files and demands payment (ransom) for the decryption key

Virus: Malicious code that attaches to legitimate files and replicates when the file is opened or shared

⚡ Security Methods — One-Line Revision Summary

Firewall: Monitors/filters network traffic — blocks unauthorised connections by IP, port, protocol

Encryption: Scrambles data so intercepted data cannot be read without the decryption key

Password/PIN: Knowledge-based authentication — proves identity before granting access

Biometrics: Something-you-are authentication — fingerprint, face, iris — very hard to fake

CAPTCHA: Proves human interaction — prevents automated bot attacks on login forms

MFA: Two or more authentication factors — even stolen password is insufficient alone

Anti-malware: Detects/removes malicious software using signature databases and heuristics

WPA2/WPA3: Encrypts Wi-Fi traffic — prevents eavesdropping on wireless networks

VPN: Encrypted tunnel through public internet — hides data and identity on public Wi-Fi

Access rights: Per-user/group file permissions — prevents unauthorised read/write/delete

Transaction logs: Records all system events — forensic evidence; detects insider threats

Backups: Copies of data stored separately — last line of defence against ransomware/failure

⚡ LAN & Client-Server Benefits — Quick Revision

LAN Benefits (2.4.3): Shared peripherals │ Shared data │ Flexible access │ Media streaming │ Communication │ Shared internet

Client-Server (2.4.4): User access rights control │ Centralised admin │ Centralised backup │ Shared software │ Shared storage │ Roaming profiles

P2P: Simple; cheap; no server needed; good for home/tiny groups; poor security; no central admin

Client-Server: Secure; centralised; scales to large orgs; expensive server; needs IT staff; powerful
