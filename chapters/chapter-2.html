1. What Is an Algorithm?

An algorithm is a precise, step-by-step sequence of instructions that solves a problem or performs a task. Every step must be unambiguous (only one possible meaning), the steps must be in a logical order, and the algorithm must eventually finish. A recipe, the instructions for assembling flat-pack furniture, and a program that finds your highest test score are all algorithms.

PropertyWhat it meansIf it's missing…
Precise / unambiguousEach step has exactly one interpretation"Add some flour" — a computer cannot guess how much
OrderedSteps happen in a defined sequenceBaking the cake before mixing the ingredients fails
FiniteThe algorithm must terminateA loop that never ends never produces an answer
EffectiveIt actually solves the stated problem for all valid inputsAn algorithm that only works for some inputs has a logic error

Algorithms are used in two directions in this course: designing solutions to new problems, and reading existing algorithms to work out what they do (often using a trace table). Paper 1 tests both.

💡 Three Ways to Express the SAME Algorithm

1. Written description: numbered steps in English — good for explaining to people.

2. Flowchart: standard symbols joined by arrows — good for visualising decisions and loops.

3. Program code: precise enough for a computer to execute — in this course, Python.

The logic is identical in all three; only the notation changes. Exam questions frequently give you one form and ask you to interpret or complete another.

2.1 Variables and Assignment

A variable is a named location in memory that stores a value which can change while the program runs. Assignment uses = and means "store the value on the right in the variable named on the left" — it is NOT the maths equals sign.

score = 0            # create variable score, store 0 in it
score = score + 1    # take the current value (0), add 1, store the result (1)
name = input("Enter your name: ")      # input is always a string
age  = int(input("Enter your age: "))  # convert the string to an integer
print("Hello", name)                   # output to the screen
⚡ EXAM TIP

x = x + 1 confuses many candidates. Read it right-to-left: "work out x + 1 using the CURRENT value of x, then store the answer back in x." In a trace table, this line creates a NEW value in the x column.

A flowchart shows an algorithm as standard symbols connected by arrows (flow lines). You must recognise and use these symbols exactly — examiners penalise the wrong shape.

3.1 Building a Flowchart — Decision and Loop

Loops in flowcharts are made by drawing a flow line from a decision diamond back up to an earlier symbol. Here is the structure for a program that keeps asking for a password until it is correct, shown as a written description and as the equivalent Python:

WRITTEN DESCRIPTION                      FLOWCHART STRUCTURE
1. Start.                                START (oval)
2. Ask the user for the password.          ↓
3. Is it equal to "open123"?             INPUT pword (parallelogram)
   - No  → go back to step 2.              ↓
   - Yes → continue.                     pword == "open123"? (diamond)
4. Display "Hello".                        ├─ No → arrow loops back to INPUT
5. Stop.                                   └─ Yes ↓
                                         OUTPUT "Hello" (parallelogram)
                                           ↓
                                         STOP (oval)
# The same algorithm in Python
pword = input("Password? ")
while pword != "open123":
    pword = input("Password? ")
print("Hello")
⚡ EXAM TIP — Drawing Flowcharts

Marks are routinely lost for: missing START/STOP terminators, decision diamonds without BOTH branches labelled (Yes/No or True/False), arrows missing their direction, and input written inside a rectangle. Check all four before moving on. If a question asks you to COMPLETE a flowchart, the empty shapes tell you what kind of statement belongs in each gap.

4. Reading Algorithms — Worked Python Examples

Paper 1 expects you to read short Python programs and state what they do. Build the habit of reading line by line, tracking each variable. Two staple patterns appear constantly — totalling and maximum-finding:

4.1 Pattern 1 — Running Total

marks = [12, 9, 17, 4]
total = 0                    # accumulator starts at 0
for mark in marks:           # repeat once per item
    total = total + mark     # add each item to the running total
print(total)                 # outputs 42

4.2 Pattern 2 — Finding the Maximum

marks = [12, 9, 17, 4]
highest = marks[0]           # assume the first item is the highest so far
for mark in marks:
    if mark > highest:       # found a bigger one?
        highest = mark       # remember it
print(highest)               # outputs 17
📌 Recognise the Pattern, Name the Purpose

"State the purpose of this algorithm" questions want the big picture, not a line-by-line story. Correct answer: "It finds and outputs the largest value in the list." Weak answer (scores poorly): "It sets highest to marks[0], then loops through…". Describe WHAT it achieves, not HOW each line works — unless the question explicitly asks how it works.

5. Trace Tables — Following an Algorithm by Hand

A trace table records the value of every variable, condition and output line by line as an algorithm executes. It is the standard tool for predicting output, understanding unfamiliar code and hunting down logic errors. One column per variable (plus columns for any condition tested and for output); a new entry each time something changes.

⚡ EXAM TIP — Trace Table Discipline

(1) Only write a value in a column when it CHANGES — copying every value into every row invites mistakes. (2) Evaluate the loop condition one final time to show WHY the loop stops — examiners often allocate a mark to the final False. (3) Output goes in the output column ONLY when a print line actually runs. (4) Work with the values given in the question, never values you expect.

6. Errors in Algorithms — Syntax vs Logic

Spec point 1.1.4 requires you to identify and fix two kinds of error. Knowing the difference is one of the most frequently examined facts in Topic 1.

Syntax errorLogic error
DefinitionThe code breaks the grammar rules of the languageThe code runs, but the algorithm itself is wrong, so the output is incorrect
Does it run?No — the translator refuses it and reports the errorYes — it runs to completion (or loops forever) without complaint
How it is foundAutomatically, by the interpreter/compiler or IDE highlightingBy TESTING — comparing actual output with expected output, often using a trace table
ExamplesMissing bracket or colon; misspelt keyword (whlie); unmatched quote marksUsing > instead of >=; adding instead of subtracting; initialising a total to 1 instead of 0; looping one time too many/few

6.1 Spot the Errors — Worked Example

# Intended purpose: output the average of the marks
marks = [10, 20, 30]
total = 0
for mark in marks
    total = total + mark
average = total / 2
print(average)
LineErrorTypeCorrection
for mark in marksMissing colon at the end of the for statementSyntax — the program will not run at allfor mark in marks:
average = total / 2Divides by 2, but there are 3 marks — runs fine, wrong answer (30 instead of 20)Logic — only testing reveals itaverage = total / 3 (better: total / len(marks))
⚠️ The Examiner's Favourite Trap

A program that produces output is NOT necessarily correct. "The program runs without any error messages" tells you only that there are no syntax errors. Logic errors hide inside running programs — which is exactly why trace tables and testing exist.

7. Algorithm Efficiency — A First Look

Two correct algorithms can solve the same problem with very different amounts of work. At GCSE, efficiency is judged informally by counting the operations (especially comparisons) an algorithm performs — no formal Big-O notation is required.

# Task: sum the whole numbers 1 to n

# Method A — a loop: n additions, so the work grows with n
total = 0
for i in range(1, n + 1):
    total = total + i

# Method B — one calculation, however large n is
total = n * (n + 1) // 2

Both produce identical results; Method B does the same job in a single step. Chapter 3 applies this idea properly, comparing linear vs binary search and bubble vs merge sort by counting comparisons.

8. Model Answers

Study the structure of each answer. Marks are shown with (1) — note how trace-table answers earn marks for the working, not just the final value.

✎ MODEL ANSWER

[2 marks]

Question: Describe the difference between a syntax error and a logic error. [2 marks]

A syntax error breaks the grammar rules of the programming language, such as a missing colon, so the program will not run and the translator reports the error (1). A logic error is a mistake in the design of the algorithm, such as using > instead of >=, so the program runs but produces the wrong output (1).

Why this scores full marks: ✓ Each error type is defined AND its consequence stated (won't run vs runs-but-wrong) ✓ Each definition is backed with a concrete example ✓ The contrast is explicit — "describe the difference" needs both halves, not just one good definition.

✎ MODEL ANSWER

[4 marks]

Question: Complete a trace table for this algorithm and state its output. [4 marks]

total = 0
count = 1
while count <= 3:
    total = total + count
    count = count + 1
print(total)

Trace: after the first iteration total = 1 and count = 2 (1); after the second iteration total = 3 and count = 3 (1); after the third iteration total = 6 and count = 4, and the condition count <= 3 is now False so the loop ends (1). The output is 6 (1).

Why this scores full marks: ✓ Every iteration is shown with BOTH variables' values — each correct row earns its mark ✓ The final condition test (False) is stated, showing why the loop terminates ✓ The output is given separately and is consistent with the trace — because the working is visible, follow-through marking could still award later marks even if an earlier row were wrong.

✎ MODEL ANSWER

[3 marks]

Question: This algorithm should output the LOWEST value in nums, but it contains a logic error. Identify the error, explain why it causes the wrong output, and write the corrected line. [3 marks]

nums = [7, 3, 9, 5]
lowest = nums[0]
for n in nums:
    if n > lowest:
        lowest = n
print(lowest)

The error is on the line if n > lowest: — the comparison operator is the wrong way round (1). Because it replaces lowest whenever a LARGER value is found, the algorithm actually finds the maximum, so it outputs 9 instead of 3 (1). The corrected line is if n < lowest: (1).

Why this scores full marks: ✓ The faulty line is precisely identified — quoting it removes any ambiguity ✓ The explanation links the error to its visible effect on the output (9 instead of 3), proving understanding rather than guesswork ✓ The correction is written as an exact replacement line, ready to drop into the code.

9. Common Mistakes

✗ COMMON MISTAKES — DON'T DO THESE!

✗ Using the wrong flowchart shapes — input/output goes in a PARALLELOGRAM, never a rectangle; decisions go in a DIAMOND with both branches labelled Yes/No.

✗ Forgetting START and STOP terminators in a flowchart, or leaving a decision with only one exit — both are instant lost marks.

✗ In trace tables, updating a variable BEFORE the line that changes it has executed — follow the code in strict line order, one change at a time.

✗ Running a loop one time too many or too few in a trace — check the condition carefully: count <= 4 runs for count = 1, 2, 3, 4; count < 4 stops after 3.

✗ Saying a logic error is "an error the program shows you" — it is the opposite: the program runs silently and gives WRONG OUTPUT; only testing reveals it.

✗ Describing an algorithm's purpose by narrating every line — "state the purpose" wants the overall effect in one sentence (e.g. "it outputs the average of the list").

✗ Treating = as "equals" — it is assignment (store this value). The comparison operator is ==. Mixing them up creates both syntax and logic errors.

✗ Ignoring the Edexcel pseudocode command set — exam algorithms are printed in it (SET…TO, SEND…TO DISPLAY, RECEIVE…FROM KEYBOARD). You can ANSWER in any valid notation, but you must be able to READ the official pseudocode accurately.

11. Quick Reference — Key Terms & Revision

★ QUICK REFERENCE — KEY TERMS

Algorithm: A precise, step-by-step sequence of instructions that solves a problem; must be unambiguous, ordered and finite

Written description: An algorithm expressed as numbered steps in plain English

Flowchart: An algorithm expressed in standard symbols: oval terminator, rectangle process, parallelogram input/output, diamond decision, double-barred subprogram box, joined by arrows

Pseudocode: Structured 'code-like' writing for expressing algorithms. Edexcel 4CP0 uses a published command set: SET…TO, SEND…TO DISPLAY, RECEIVE…FROM, IF…END IF, WHILE…END WHILE, REPEAT…UNTIL, FOR…END FOR

MOD and DIV: Edexcel pseudocode operators for remainder and integer division (Python: % and //)

Variable: A named memory location storing a value that can change while the program runs

Assignment ( = ): Store the value of the right-hand side in the variable on the left; x = x + 1 increases x by 1

Trace table: A table recording each variable, condition and output line by line as an algorithm executes — used to predict output and find logic errors

Syntax error: Code that breaks the language's grammar rules (missing colon/bracket, misspelt keyword); the program will not run; reported by the translator

Logic error: A design mistake (wrong operator, wrong initial value, off-by-one loop); the program runs but the output is wrong; found by testing/tracing

Efficiency: How much work (e.g. how many comparisons) an algorithm needs — fewer operations for the same result = more efficient

Stock patterns to recognise on sight: running total (total = total + x in a loop) · counter (count = count + 1) · maximum/minimum (compare-and-replace inside a loop)
