1. The Von Neumann Architecture [Spec 4.2.3]

Almost all modern computers use the von Neumann architecture. Its key idea is the stored program concept: both the program instructions and the data they work on are held together in the same main memory. The CPU fetches instructions from memory one at a time and executes them in order.

💡 Stored program concept

Because instructions are stored in memory (not hard-wired), the same computer can run any program simply by loading different instructions — this is what makes computers general-purpose.

1.1 The Input–Process–Output Model [Spec 4.1.1]

Every computer system follows the input–process–output (IPO) model: data goes IN (keyboard, sensor, file), the CPU PROCESSES it (calculations, decisions), and results come OUT (screen, speaker, motor, file). Storage sits alongside, holding data between runs.

StageExample: supermarket checkout
InputBarcode scanned
ProcessPrice looked up, total updated
OutputPrice shown on display, receipt printed

2. Inside the CPU [Spec 4.2.1]

The CPU (Central Processing Unit) carries out program instructions. You need to know these components:

ComponentRole
Control Unit (CU)Decodes instructions and sends control signals to coordinate the rest of the CPU and memory.
Arithmetic Logic Unit (ALU)Performs all arithmetic (add, subtract) and logical operations (AND, OR, comparisons).
RegistersTiny, extremely fast stores inside the CPU that hold one value during processing (e.g. the program counter, which holds the address of the next instruction).
ClockSends out regular electrical pulses that synchronise the CPU's operations; speed measured in hertz (GHz).
BusesSets of wires carrying data (data bus), memory locations (address bus) and signals (control bus) between the CPU and memory.

3. The Fetch–Decode–Execute Cycle [Spec 4.2.3]

The CPU repeats this cycle continuously, billions of times per second:

StageWhat happens
1. FetchThe next instruction is copied from main memory into the CPU (its address comes from the program counter, which then moves on).
2. DecodeThe control unit works out what the instruction means and what needs to be done.
3. ExecuteThe instruction is carried out — for example the ALU performs a calculation, or data is moved. The result may be stored back in memory or a register.
⚡ EXAM TIP

Remember the order: Fetch → Decode → Execute, then repeat. The program counter keeps track of which instruction comes next.

4. CPU Performance [Spec 4.2.4]

FactorEffect on performance
Clock speedHigher GHz = more fetch–decode–execute cycles per second = more instructions processed. 3.0 GHz = 3 billion cycles per second.
Number of coresEach core can process instructions independently. A quad-core CPU can work on four tasks at once (if the software supports it).
Cache sizeLarger cache stores more frequently-used data and instructions close to the CPU, so it spends less time waiting for slower RAM.

5. Main Memory — RAM, ROM & Cache [Spec 4.2.2]

MemoryVolatile?Purpose
RAM (Random Access Memory)Volatile (lost when power off)Holds the programs and data currently in use. The more RAM, the more can run at once without slowing down.
ROM (Read Only Memory)Non-volatileHolds the startup (bootstrap) instructions that run first when the computer is switched on. Cannot normally be changed.
CacheVolatileVery small, very fast memory inside/near the CPU holding the most frequently used data to speed up processing.
💡 Volatile vs non-volatile

Volatile memory loses its contents when power is removed (RAM, cache). Non-volatile memory keeps its contents (ROM, secondary storage).

5.1 Virtual Memory [Spec 4.2.2]

When RAM is full, the operating system can use part of secondary storage as virtual memory — an overflow area. Pages of data not currently needed are swapped out of RAM onto the disk and swapped back when required.

⚠️ The trade-off

Virtual memory lets more programs run than physical RAM alone allows, but secondary storage is far slower than RAM, so heavy swapping (‘thrashing’) makes the computer feel sluggish. The long-term fix is more RAM.

6. Secondary Storage [Spec 4.2.5]

Secondary storage is non-volatile and is needed to keep programs and files permanently (RAM cannot, because it is volatile and too small/expensive).

TechnologyHow it stores dataStrengthsWeaknesses
Magnetic (HDD, tape)Magnetised areas on spinning platters/tapeVery high capacity, low cost per GBMoving parts → slower, fragile, noisier
Optical (CD/DVD/Blu-ray)Pits & lands read by a laserCheap, portable, good for distributionLow capacity, slow, easily scratched
Solid state (SSD, USB, SD)Flash memory chips — no moving partsFast, durable, silent, low powerMore expensive per GB
⚡ EXAM TIP

When choosing storage for a scenario, weigh up capacity, speed, portability, durability and cost per GB. E.g. a laptop for travel → SSD (durable, fast); a data-centre archive of huge backups → magnetic tape (cheap per GB).

6.1 Cloud Storage [Spec 4.2.6]

Cloud storage means storing data on remote servers in data centres, accessed over the internet (e.g. Google Drive, OneDrive, iCloud).

7. Embedded Systems [Spec 4.2.7]

An embedded system is a computer built into a larger device to perform one dedicated function. It usually uses a small microcontroller with its software (firmware) stored permanently in ROM.

Embedded systemDedicated job
Washing machine controllerRuns the selected wash programme
Car anti-lock braking (ABS)Controls braking pressure to prevent skidding
Smart thermostatMaintains the set room temperature
Microwave ovenControls power level and timer
💡 Embedded vs general-purpose

A general-purpose computer (laptop, phone) runs many different programs. An embedded system does one fixed task, so it is cheaper, smaller, more reliable and uses less power.

9. Common Mistakes

✗ COMMON MISTAKES — DON'T DO THESE!

✗ Saying RAM is non-volatile — it is volatile; ROM is non-volatile.

✗ Confusing main memory (RAM/ROM) with secondary storage (HDD/SSD) — they are different things.

✗ Giving the fetch–decode–execute stages in the wrong order.

✗ Saying "more clock speed always means faster" without mentioning cores and cache also matter.

✗ Describing an SSD as having moving parts — it uses flash memory with no moving parts.

✗ Saying an embedded system can run any program — it does one dedicated task.

✗ Forgetting the von Neumann key point: instructions AND data share the same memory.

11. Quick Reference — Key Terms

★ QUICK REFERENCE

Von Neumann / stored program: instructions and data held together in main memory.

CU: decodes & coordinates. ALU: arithmetic & logic. Registers: tiny fast stores. Clock: synchronises (GHz).

FDE cycle: Fetch → Decode → Execute, repeated.

Performance factors: clock speed, cores, cache.

RAM: volatile working memory. ROM: non-volatile startup. Cache: fast frequently-used data.

Storage: magnetic (cheap, big), optical (portable, small), solid state (fast, durable).

Embedded system: dedicated computer inside a device; firmware in ROM.
