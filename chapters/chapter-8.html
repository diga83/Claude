2. The Operating System [Spec 3.2.2]

The operating system (OS) is the most important piece of system software. Its main functions are:

FunctionWhat it does
File managementCreating, saving, moving, renaming and deleting files and folders
Process managementScheduling CPU time between running programs so several can run at once (multitasking)
Peripheral managementControlling input/output devices using device drivers
Memory managementAllocating RAM to programs and reclaiming it when finished
User managementUser accounts, log-ins and access rights
SecurityPasswords, permissions and protecting data

3. Utility Software [Spec 3.2.3]

Utility software performs maintenance and protection tasks that keep the system running well.

UtilityPurpose
Anti-malwareScans for and removes viruses, worms and other malware
Firewall (software)Monitors and filters network traffic by rules
BackupMakes copies of data so it can be restored. A full backup copies everything; an incremental backup copies only what has changed since the last backup
CompressionReduces file size for storage or transfer (e.g. ZIP)
DefragmentationRearranges fragmented file pieces on a magnetic hard disk so they are contiguous, speeding up access. Not needed for SSDs.

4. High-Level vs Low-Level Languages [Spec 3.3.1]

FeatureHigh-level (e.g. Python)Low-level (machine code / assembly)
Looks likeEnglish-like keywordsBinary, or short mnemonics (assembly)
Easy to write/read?YesNo — slow and difficult
Portable across machines?Yes (after translation)No — specific to one processor
Needs translating?YesMachine code: no; assembly: by an assembler
One statement equalsMany machine instructionsOne (or few) machine instructions
💡 Machine code & assembly

Machine code is binary instructions the CPU runs directly. Assembly language uses short mnemonics (e.g. ADD, LDA) and is translated to machine code by an assembler. Both are low-level.

5. Why Translation Is Needed [Spec 3.3.2]

A CPU can only execute machine code. Programs written in a high-level language must therefore be translated into machine code before they can run. The two main translators are the compiler and the interpreter.

6. Compiler vs Interpreter [Spec 3.3.3]

FeatureCompilerInterpreter
How it translatesThe whole program at onceOne line at a time, as it runs
Output producedA separate executable fileNo executable — translates each run
Error reportingReports all errors after compilingStops at the first error it reaches
Speed of finished programRuns quickly (already machine code)Slower (translated each time)
Best forReleasing/distributing finished softwareDeveloping and debugging (Python uses one)
⚡ EXAM TIP

A handy way to remember: a compiler is like translating a whole book before anyone reads it; an interpreter is like a live translator speaking sentence by sentence. Python is interpreted, which is why errors appear as it runs.

State two functions of an operating system. [2 marks]

Memory management — allocating RAM to running programs (1). File management — creating, saving and deleting files (1).

✎ MODEL ANSWER

[4 marks]

Explain two differences between a compiler and an interpreter. [4 marks]

A compiler translates the whole program in one go and produces an executable file (1), whereas an interpreter translates and runs the code one line at a time and produces no executable (1). A compiler reports all errors together after compiling (1), while an interpreter stops at the first error it meets, which can make debugging easier (1).

Why this scores full marks: ✓ Whole-program vs line-by-line difference developed ✓ Error-reporting difference developed.

✎ MODEL ANSWER

[3 marks]

Explain why high-level languages need to be translated. [3 marks]

A CPU can only execute machine code, which is binary (1). High-level languages such as Python use English-like keywords that the CPU cannot run directly (1), so a translator (compiler or interpreter) is needed to convert the source code into machine code before it can be executed (1).

Why this scores full marks: ✓ CPU runs only machine code ✓ High-level not directly executable ✓ Translator converts it.

8. Common Mistakes

✗ COMMON MISTAKES — DON'T DO THESE!

✗ Calling the operating system "application software" — it is system software.

✗ Saying a compiler runs the program line by line — that is an interpreter.

✗ Saying an interpreter produces an executable file — it does not.

✗ Listing "Microsoft Word" as a function of the OS — it is application software.

✗ Saying SSDs need defragmenting — only magnetic hard disks benefit from it.

✗ Confusing assembly language with a high-level language — assembly is low-level.

✗ Forgetting that a CPU can only execute machine code.

10. Quick Reference — Key Terms

★ QUICK REFERENCE

System software: OS, utilities, drivers. Application software: user tasks (Word, browser).

OS functions: file, process, peripheral, memory, user management + security.

Utilities: anti-malware, firewall, backup (full/incremental), compression, defragmentation (HDD only).

Low-level: machine code (binary), assembly (mnemonics → assembler). High-level: Python — portable, English-like, needs translating.

Compiler: whole program → executable; errors after; fast to run.

Interpreter: line by line; no executable; stops at first error; good for development.
