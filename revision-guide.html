1 Digital Devices

Device types you must know

DeviceKey fact
MainframeHuge organisations (banks, gov). Many users, massive data, 24/7.
Embedded microprocessorChip inside a product (washing machine). ONE task. Not reprogrammable.
DesktopStationary. Mains power. Most performance per £. Easily upgraded.
LaptopPortable. Battery. Some are 'desktop replacement' = high-spec.
SmartphoneConvergent: phone + camera + GPS + browser. SIM = cellular only (not Wi-Fi).
TabletTouchscreen. No keyboard by default. Larger than phone.
GPS deviceRECEIVE-ONLY. Does not transmit. Common trap!

The 9 features — memorise (P-P-S-U-C-M-E-E-S)

  • Portability
  • Performance
  • Storage
  • User interface
  • Connectivity
  • Media support
  • Energy consumption
  • Expansion capability
  • Security features
⚡ Key exam point

Convergence: Different device TYPES becoming more similar over time.
Multifunctional: ONE device combining many functions.
Two different concepts — the exam tests both.

⚠ Common trap

Never say "GPS sends data to satellites" — it's receive-only. Satellites transmit DOWN; your device only receives.

2 Software

The hierarchy

System software (manages hardware) = Operating System + Utility software
Application software = what the user interacts with (Word, browser, etc.)

5 OS functions — know all

  1. Manages hardware — translates between user/apps and hardware
  2. Memory management — allocates RAM to running programs
  3. Resource management — shares CPU, printers, files
  4. Security — user accounts, passwords, access rights
  5. Print spooling — queues jobs so user can keep working

Open source vs Proprietary

Open SourceProprietary
Source codePublic, modifiableHidden, illegal to crack
CostUsually freePaid licence

ExamplesLinux, Firefox, GIMPWindows, Adobe Photoshop
⚡ Key exam point

Why update software (3 reasons): fix bugs / patch security holes / add features.
Risks of NOT updating: malware vulnerability, crashes, file incompatibility.

⚡ Capacity units — MEMORISE

1 byte = 8 bits | 1 KiB = 1,024 bytes | 1 MiB = 1,024 KiB | 1 GiB = 1,024 MiB | 1 TiB = 1,024 GiB
Exam uses KiB/MiB/GiB (binary, ×1024) — NOT KB/MB/GB (×1000).

⚠ Common trap

Recordable (R) = write ONCE only. Rewritable (RW) = write many times.

4 Memory, Processors & ICT Systems

RAM vs ROM — the key comparison

FeatureRAMROM
Volatile?YES — loses content when offNO — keeps content
Read/WriteRead AND writeREAD ONLY
HoldsRunning programs, open filesBIOS / boot instructions
More of it meansMore programs at once(Size doesn't change)

Fetch-Decode-Execute cycle

1. FETCH instruction from RAM → 2. DECODE it → 3. EXECUTE (ALU acts) → 4. STORE result. Repeats billions of times per second.

4 factors affecting CPU speed

  • Clock speed (GHz) — cycles per second
  • Number of cores — parallel work
  • Cache size — fast memory near CPU
  • RAM size — fewer disk swaps
💡 Flash memory

Non-volatile (like ROM) BUT can be rewritten. Used in SSDs, USB drives, SD cards, smartphones.

5 Connectivity & Networks

Network types

  • LAN (Local) — one site, one organisation. Example: school.
  • WAN (Wide) — many sites, often global. Example: the internet.
  • PAN (Personal) — around one person. Example: phone + headphones + watch.

Wi-Fi vs Bluetooth (classic exam Q)

Wi-FiBluetooth
RangeLong (~50m)Short (~10m)
SpeedFast (>100 Mbps)Slow (~2 Mbps)
Best forInternet, filesPairing: audio, peripherals
Power useHigherLower

Mobile evolution

1G voice only → 2G + SMS → 3G mobile internet → 4G HD streaming → 5G ultra-fast, low-latency.

⚡ Bandwidth vs Latency

Bandwidth: Max data/second. Higher = faster downloads.
Latency: Delay before response. LOWER is better. Critical for video calls and gaming.

6 Network Benefits & Security

P2P vs Client-Server

Peer-to-PeerClient-Server
StructureAll devices equalDedicated server + clients
CostLowHigh (server hardware)

8 security threats

  • Malware — malicious software (viruses, etc.)
  • Phishing — fake email tricking user (RELIES ON USER MISTAKE)
  • Pharming — silent DNS redirect to fake site (NO USER MISTAKE)
  • Hacking — unauthorised system access
  • Ransomware — encrypts your files; demands payment
  • Social engineering — tricks PEOPLE not systems
  • Identity theft — impersonating someone via stolen data
  • DOS attack — floods server with traffic

Security methods

Firewall (filters traffic) · Encryption (ciphertext + key) · WPA2/WPA3 (Wi-Fi encryption) · VPN (encrypted tunnel) · MFA (password + phone code) · Biometrics · Access rights · Backups · Anti-malware · Transaction log

⚡ THE GOLDEN RULE

Every "Explain" question: feature (1 mark) + reason or consequence (1 mark). "Encryption protects data" = 0 marks. "Encryption converts data to ciphertext (1) so even if intercepted it cannot be read without the key (1)" = 2 marks.

7 Operating Online — Risks & Impacts

Phishing vs Pharming (THE distinction)

Phishing: Fake email/link asking you to give credentials. USER MISTAKE required.
Pharming: DNS attack silently redirects you to fake site. NO user mistake needed.

Working from home — both sides

Individual ✓Individual ✗
No commute, flexible hours, work-life balanceDistractions, isolation, own equipment
Employer ✓Employer ✗
Lower costs, wider talent poolHarder to manage, security risks

GDPR / DPA 2018 — rights

  • Right to access — see what data is held
  • Right to erasure ('right to be forgotten')
  • Right to correction — fix inaccuracies
  • Data must be: lawful, accurate, secure, used only for stated purpose

Digital divide

Gap between those WITH and WITHOUT good internet/devices. Causes: cost, rural location, age, disability. Consequences: excluded from jobs, education, services.

Health risks

RSI (repetitive strain) — long typing/mouse use. Fix: breaks, ergonomic kit.
Eye strain — staring at screen. Fix: 20-20-20 rule, anti-glare.
Back/neck pain — poor posture. Fix: adjustable chair, monitor at eye level.

10 Paper 2 — Software Skills Reference

Database essentials

  • Field = one column (e.g. LastName)
  • Record = one row (all data about one entity)
  • Primary key = unique identifier (e.g. StudentID)
  • Foreign key = links to another table's primary key
  • Validation = auto rule-check (FORMAT)
  • Verification = human check vs source (correctness)

6 validation checks

Presence (not blank) · Range (5-120) · Type (numbers only) · Length (5-8 chars) · Format (DD/MM/YYYY) · Lookup (from list)

Absolute vs Relative references

Relative (A1): adjusts when copied. Absolute ($A$1): stays fixed. Use $ to lock cells you don't want to change (tax rate, conversion factor).

📝 Exam Technique — Last-Minute Tips

CompareSimilarities AND differences1-2 per comparison

JustifyReasons supporting choiceScenario-specific

8 last-minute tips

  1. Underline the command word + note mark allocation
  2. Use scenario context — generic answers score less
  3. Develop every point — 'because', 'so that', 'which means'
  4. Both sides for Discuss/Evaluate — one-sided caps at 50%
  5. Technical vocabulary — "encryption", not "thingy"
  6. Match length to marks — 6 marks = 6 distinct points
  7. Full sentences for 4+ mark answers — not bullets
  8. 1 minute per mark. Paper 1: 90 min / 100 marks. Save 5 min to check.
⚡ THE GOLDEN RULE

Every Explain = feature (1) + reason/consequence (1). "Encryption protects data" = 0 marks. "Encryption converts data into ciphertext (1) so even if intercepted it cannot be read without the key (1)" = 2 marks.

⚠ Mistakes that lose marks every year
  • "It makes things faster" — not specific. Say WHAT is faster and WHY.
  • Mixing validation and verification
  • Mixing phishing (user mistake) and pharming (silent)
  • Generic answers when a scenario is given
  • Repeating the same point in different words
